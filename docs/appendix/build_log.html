    Two infrastructure decisions (deviations from the literal spec, intent preserved):

    1. embed-resources: true turned OFF (deviates from C10). It is incompatible with a cross-linked multi-page website: Quarto tries to inline every linked sibling page, producing a page-on-page cascade (notation_table hit 36 MB, far over the C4 8 MB ceiling, with “Could not fetch resource” warnings). Offline use is instead achieved via Quarto’s standard local site_libs/ bundling. Net effect: same offline guarantee, pages ~50–60 KB instead of 12–36 MB.
    2. KaTeX vendored locally (assets/katex/). Quarto’s html-math-method: katex defaults to the jsdelivr CDN (violates C8/6.5 offline). Fetched KaTeX 0.16.11 via npm at build time, copied the dist (js/css + 60 font files) into assets/katex/, and set html-math-method: {method: katex, url: "assets/katex/"} + resources: assets/katex/**. Quarto depth-adjusts the URL per page (../assets/katex/... in subdirs), so math is fully offline at every depth. (Runtime is offline; only the one-time build-time npm fetch used the network.)
