Exercise Dependency Map

Cross-method · The six course exercises are not a flat list — each one exercises a specific set of method pages, and they stack into a natural learning order: clean data first, then a probabilistic classifier, then regression with shrinkage, then a multiclass bake-off, then the evaluation machinery, and finally unsupervised segmentation. This page maps which exercise notebook builds on which method (every edge taken straight from that exercise’s “Method page(s) it links to” and its solution walkthrough — see phase0/exercise_0*.md), colors the method nodes by family, and proposes a study order. Use it to see, at a glance, what you must already understand before opening a given exercise — and which method page to revise when an exercise gives you trouble.

The suggested learning path (1 → 6). Work the exercises in this order — it matches how the course layers skills: (1) Titanic preprocessing — raw-data hygiene with no model, the foundation every later exercise assumes. (2) Spam / naive Bayes — your first classifier, built from scratch and with sklearn, on text features. (3) House prices — regression: OLS baseline then Ridge/Lasso, the exam’s Assignment-1 skill. (4) MNIST digits — a multiclass bake-off (logistic vs kNN vs trees vs naive Bayes vs SVM). (5) Model selection — the evaluation toolkit (cross-validation, GridSearchCV, confusion matrices) that makes (3)–(4) rigorous. (6) Customer segmentation — the only unsupervised exercise (K-means + PCA). Preprocessing (1) underpins all; evaluation (5) is the lens you re-apply to everything before it.

The map

Read it left-to-right: each exercise (left column, slate) connects to the methods it exercises (right column, colored by family). An edge means “this exercise’s solution actually uses this method” — nothing is drawn that isn’t in the extract. Methods with a dedicated study page are linked from the table below; naive Bayes and SVM appear because exercises use them but they are drill-only / not covered as method pages, so they carry no family link.

// --- layout geometry: two columns, evenly spaced rows ---
W = 720
rowH = 46
topPad = 34
xL = 215     // x of exercise (right edge of left labels)
xR = 505     // x of method (left edge of right labels)
H = topPad + Math.max(exercises.length, methods.length) * rowH

exPos = new Map(exercises.map((e, i) => [e.id, topPad + i * rowH]))
mPos  = new Map(methods.map((m, i)  => [m.id, topPad + i * rowH]))

linkData = edges.map(d => ({
  x1: xL, y1: exPos.get(d.ex),

Note

Two notes on faithfulness to the sources. (i) Exercise 01 has no method edges because its extract is explicit: “None of the modeling methods directly… It is foundational/preprocessing.” It is the shared prerequisite for everything downstream, not a consumer of a method page. (ii) Naive Bayes and SVM appear as methods used by exercises 02/04 but have no dedicated method page — naive Bayes is drill-only (taught in lecture, exercised here, but excluded from the 16 method pages per the recurrence map); SVM (SVC) is used as a comparison classifier but is noted in the digits/model-selection extracts as not covered in course detail. They are shown for completeness but carry no method-page link.

How to use this with the rest of the site

  • Stuck on an exercise? Find its row above and open the listed prerequisite method pages first — those are the exact methods its solution uses.
  • Revising a method? Trace its node in the map back to the exercises that exercise it — that gives you ready-made practice problems for that method.
  • Cross-method practice: exercises 03–05 are where methods compete on one dataset. For head-to-head comparisons on shared datasets see the Showdowns page; for choosing among them see the Decision Dashboard and Family Comparisons.
