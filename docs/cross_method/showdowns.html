Showdowns

Cross-method · two head-to-head bake-offs on the course’s own common datasets — same data, same split, many models — so the differences between methods (not the dataset) are what you read. The classification showdown lines up Logistic Regression, LDA, kNN, a Decision Tree and a Random Forest on a shared 2-D boundary; the regression showdown lines up OLS, Ridge, Lasso, a Tree and a Random Forest on Hitters. Every number on this page is computed in the course .venv — no values are transcribed by hand.

Why a showdown earns its place. Each method page argues in isolation why its model draws the boundary or fits the curve it does. A showdown puts them on the same canvas: with Age and Fare held fixed, the only thing that changes between the five panels below is the inductive bias of the model — so you can literally see linear-vs-wiggly-vs-staircase side by side. The decision dashboard turns these observations into a “which model when?” guide; this page is the empirical evidence behind it.

1. Classification showdown — five decision boundaries on one 2-D dataset

The setup is deliberately minimal so the boundary shape is the whole story. We load the Titanic training set, keep the two numeric features Age and Fare (dropping rows missing either — 714 of 891 rows survive), and predict Survived. Five classifiers are fit on the standardized features, then asked to predict the class at every point of a coarse 40×40 grid spanning the Age/Fare range; colouring the grid by predicted class draws each model’s decision region (all computed via ./.venv/Scripts/python.exe, fixed random_state=1):

sub = pd.read_csv("course_materials/Data/Titanic data/train.csv")[["Age","Fare","Survived"]].dropna()  # 891 → 714
X, y = sub[["Age","Fare"]].values, sub["Survived"].values
Xs = StandardScaler().fit_transform(X)                       # scale so kNN distance is fair
models = {
    "Logistic":   LogisticRegression(max_iter=1000),
    "LDA":        LinearDiscriminantAnalysis(),
    "kNN (k=15)": KNeighborsClassifier(n_neighbors=15),
    "Tree (d=3)": DecisionTreeClassifier(max_depth=3, random_state=1),
    "RF (d=3)":   RandomForestClassifier(n_estimators=100, max_depth=3, random_state=1),
}

The in-sample (training-set) accuracies are close — the two features alone are weak predictors of survival, so this is a boundary-shape comparison, not a leaderboard — (computed):

Reading it — linear vs local vs axis-aligned. The two linear-family classifiers, Logistic Regression and LDA, produce a single straight cut across the plane — exactly what their §1/§2 promise: both place a hyperplane, differing only in how (logistic fits the log-odds directly; LDA assumes Gaussian classes with a shared covariance and gets a line as a consequence, LDA §8). Here they tilt almost identically, the textbook “on data where LDA’s assumptions roughly hold, the two land in the same neighbourhood” (logistic §6, LDA §4). Neither can bend: if survival depended on Age and Fare in a curved way, both would underfit it the same way.

kNN (k=15) is the visible opposite. Its region is irregular and locally wiggly — pockets of “survived” appear wherever a cluster of survivors sits, because each grid cell is labelled by a majority vote of its 15 nearest training points. This is the non-parametric flexibility kNN §1 advertises (“it can carve out arbitrarily wiggly decision boundaries”) and the variance kNN §2 warns about: with a smaller k the region would fragment further; with a much larger k it would smooth toward the global majority. It draws no global rule — only “who is nearby.”

The two tree-family models show the third geometry: axis-aligned steps. The single depth-3 Decision Tree partitions the plane into a handful of rectangular blocks with perpendicular edges — never a diagonal — because every split is a threshold on one feature at a time (decision-trees §1: “staircase boundaries… perpendicular cuts”). The depth-3 Random Forest averages 100 such shallow trees, each grown on a bootstrap sample with a random feature subset, so its boundary is a smoother, finer version of the same blocky shape — the variance reduction of §1 made visible: the jagged single-tree steps soften into a more stable region without ever becoming a smooth curve. A tree wins when the true boundary is blocky; it pays a jagged-staircase tax when the truth is a clean diagonal — which is exactly the trade the decision dashboard encodes.

Reading it — OLS overfits, shrinkage helps a little, the forest helps a lot. Plain OLS is the weakest of the five: test R^2 = 0.36 against a train R^2 = 0.55, the wide train–test gap that is the fingerprint of variance (OLS §4, §6). The cause is structural — 16 partly-redundant career totals (CAtBat, CHits, CRuns… all move together), so OLS fits the training sample’s noise. This is precisely the diagnosis the OLS page makes and the cue it hands to regularization.

Ridge and Lasso, with cross-validated alpha, do exactly what regularization §4 predicts: they trade a little training fit (train R^2 0.55 → 0.54) for better generalization (test R^2 0.36 → 0.38–0.39, RMSE 377 → 370–373). The gain is modest but real — the bias–variance trade-off made concrete, and the reasoning the exam grades. Note that a penalty cannot fix a wrong functional form: if the Salary surface is genuinely non-linear, shrinking linear coefficients only goes so far (regularization §2: “a penalty cannot fix a wrong functional form”).

The two tree-family models bracket the lesson. A single depth-3 Tree reaches test R^2 = 0.37 — no better than OLS — while its train R^2 (0.74) already shows the high-variance, memorize-the-sample behaviour decision-trees §1/§5 describes; “a single tree’s variance can’t be cross-validated away, only ensembled away.” And that is exactly what the depth-3 Random Forest does: averaging 100 decorrelated shallow trees lifts test R^2 to 0.59 and cuts RMSE to $304k — comfortably the best model here. It captures the non-linear, interaction-heavy structure the linear models cannot, while the bagging-plus-feature-randomness of random-forests §1 controls the variance a lone tree cannot. The ordering — RF ≫ Ridge ≈ Lasso > Tree ≈ OLS — is the cross-method story in one line: when the truth is non-linear with redundant predictors, an ensemble of shallow trees beats both the linear baseline and its regularized fixes.

3. What the two showdowns share

Both panels are the same idea told twice. In classification, model choice changes the shape of the boundary — linear (Logistic/LDA), local-wiggly (kNN), or axis-aligned-blocky (Tree/RF) — and the right choice depends on the true boundary’s geometry. In regression, model choice changes how the bias–variance budget is spent — OLS pays in variance, Ridge/Lasso buy it back with a little bias, a single Tree overfits, and the Forest spends its budget on decorrelated averaging to win. The unifying lens is bias–variance, and the practical “pick one” guide is the decision dashboard; every method’s own §2 (“when to use / when not”) is the per-model version of the same advice.
