Principal Component Analysis (PCA)

Unsupervised · the workhorse of linear dimensionality reduction — it rewrites your features as a handful of uncorrelated directions that pack in as much variance as possible, for visualization, noise reduction, or compression. Siblings: LDA (the supervised cousin — maximizes class separation, not raw variance), K-Means (the natural downstream step — reduce, then cluster), Regularization (the rival fix for many/correlated predictors — shrink the original axes instead of projecting onto new ones).

1. Essence

Principal Component Analysis takes a dataset with many (possibly correlated) features and finds a new set of axes — the principal components — that are mutually orthogonal and ordered so the first captures the most variance in the data, the second the most of what remains, and so on. Keeping only the first few components gives you a faithful lower-dimensional version of the data: fewer columns, but most of the information retained. It is a linear technique — each component is a weighted combination of the original features — and it is unsupervised: it looks only at the spread of the predictors and ignores any class labels entirely (Lecture 6, slide 9/19).

The three things people do with it are visualization, preprocessing, and compression. Visualization: project high-dimensional data down to 2 or 3 components and plot it to spot clusters, trends, and outliers. Preprocessing / noise reduction: drop the low-variance components, which often carry mostly noise, to mitigate the curse of dimensionality and feed a cleaner, smaller representation to a downstream model. Compression: store the few high-variance components instead of all original features (the Eigenfaces idea for images) (Lecture 6, slide 10/19).

The single most important practical rule is standardize first. PCA chases variance, and variance is not scale-invariant: a feature measured in large units (proline in milligrams, area in mm²) will dominate the first component purely because its numbers are bigger, not because it is more informative. Lecture 6 calls standardization “crucial for unbiased results” (slide 11/19), and the worked examples in §4 show exactly what goes wrong when you skip it. Compared with its neighbours: LDA does dimensionality reduction too, but supervised — it keeps the directions that separate the classes, not the directions of largest total spread; Regularization tackles the same many/correlated-predictor problem but by shrinking coefficients on the original (interpretable) axes rather than replacing them with components; and K-Means is the clustering step PCA most often feeds (Lecture 6, slide 18/19).

2. When to use / when not to use

Reach for PCA when…

  • You have many features, some correlated, and want to compress them into a few uncorrelated directions while keeping most of the information — read off how much you keep from the explained-variance ratio (Lecture 6, slide 6/19).
  • You want to visualize high-dimensional data in 2D/3D to look for clusters, trends, or outliers before modelling (Lecture 6, slide 10/19).
  • You want noise reduction / preprocessing — discard the low-variance tail of components, which is often noise, then feed the reduced data to a classifier or to K-Means (Lecture 6, slides 10/18). The exam’s Assignment 2 does exactly this: scale → PCA to 90 % variance → cluster (see §7).
  • You need compression of a large, redundant feature set (images, sensor banks).

Reach for something else when…

  • You have labels and care about class separation, not raw spread → LDA. PCA’s top component can run across the classes rather than between them, because it never sees y; LDA spends its budget on separability (the Iris contrast on the LDA page makes this vivid).
  • The structure is genuinely non-linear → PCA only finds linear directions; a curved manifold defeats it. Lecture 6 lists linearity as the first limitation (slide 11/19); reach for a non-linear reducer (t-SNE is named on slide 4/19) or a kernel method.
  • You want to keep interpretable original features and merely tame correlation/overfitting → Regularization (Ridge/Lasso) shrinks or zeros coefficients on the original axes; PCA’s components are blends of all features and are harder to read (Lecture 6 lists interpretability as a limitation, slide 11/19).
  • Outliers dominate → PCA is variance-driven, so a few extreme points can swing the components (Lecture 6, slide 11/19); diagnose and consider robust methods first.

3. Code idiom

The canonical course idiom is scikit-learn’s PCA. There is no from-scratch implementation in the lecture notebook — the eigendecomposition/SVD mechanics are left as markdown theory (notebook 10_PCA.ipynb, cell 1); see §8 for that math (marked supplemental).

Canonical (sklearn) — (notebook 10_PCA.ipynb, cell 6)

from sklearn.decomposition import PCA

pca = PCA(n_components=2)        # keep the top 2 components
pca.fit(X)                      # learns the directions from the spread of X (no y — unsupervised)
pca.components_                 # the principal axes (each a length-p combination of features)
X_proj = pca.transform(X)       # project X onto the 2 components → (n_samples, 2)
pca.explained_variance_ratio_   # fraction of total variance each component captures

The one hyperparameter you normally touch is n_components: an integer keeps that many components; a float in (0, 1) keeps the smallest number of components reaching that cumulative variance — PCA(n_components=0.90) is the exact idiom for the exam’s “90 % variance” task. The course reads off how much variance two components keep with (notebook 10_PCA.ipynb, cell 7):

sum(pca.explained_variance_ratio_.round(2))   # e.g. 0.99 for unscaled seeds

Standardize first — the pipeline idiom (notebook 10_PCA.ipynb, cell 12). Because PCA is scale-sensitive, the course wraps a StandardScaler in front of it (here also feeding a downstream classifier), so the scaling is learned on the training fold and never leaks:

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.naive_bayes import GaussianNB

std_clf = make_pipeline(StandardScaler(), PCA(n_components=2), GaussianNB())
std_clf.fit(X_train, y_train)
std_clf.named_steps['pca'].explained_variance_ratio_   # reach into a pipeline step

The reproducibility + labeling traps in the lecture notebook (phase0/disagreements.md [NB-3]). Three things in 10_PCA.ipynb cell 12 are worth fixing when you reuse it: (i) its train_test_split(features, target, test_size=0.30) has no random_state, so the accuracy printout changes every run — always set a seed (the §4 numbers below use random_state=42). (ii) The left “Training dataset after PCA” panel actually plots X_train[..., 0] and X_train[..., 1] — the first two raw features, not the PCA projection — so it is mislabeled; only the right (standardized) panel truly shows PCA output. (iii) The notebook loads ../data/seeds.csv (lowercase) while the repo file is course_materials/Data/seeds.csv (capital D) — harmless on Windows but a real path-case mismatch.

4. Worked examples

Example 1 — seeds: how much do 2 components keep, and does scaling matter?

The lecture’s first dataset is seeds.csv — 140 wheat kernels, 7 geometric features (area, perimeter, compactness, length, width, asymmetry_coefficient, grove_length), target type with 2 varieties (70 each) (notebook 10_PCA.ipynb, cells 3–4). The notebook fits PCA on the raw features (cell 6) and reports two components capture 0.99 of the variance (cell 7 idiom sum(pca.explained_variance_ratio_.round(2))):

X = seeds[['area','perimeter','compactness','length','width',
           'asymmetry_coefficient','grove_length']]
pca = PCA(n_components=2).fit(X)
pca.explained_variance_ratio_          # ≈ [0.834, 0.157]  → sum ≈ 0.991

That 99 % looks fantastic — until you remember PCA chases raw variance and these features are unscaled. area and perimeter have far larger numeric spread than compactness, so they dominate PC1 by units, not by importance. Standardize first and the picture is honest (computed via the course .venv, ./.venv/Scripts/python.exe):

seeds PCA PC1 PC1+PC2 components for ≥ 90 %
Unscaled (nb10 cell 6) 0.834 0.991 2
Standardized (StandardScaler first) 0.692 0.859 3

After standardizing, two components keep only 86 %, and you need three to clear 90 % (computed) — the cumulative-variance curve in §5 shows exactly where the 90 % line is crossed. The unscaled “99 %” was largely an artifact of area/perimeter’s units: this is the standardization lesson (Lecture 6, slide 11/19) made concrete on the course’s own dataset, and it is precisely the decision the exam’s “PCA to 90 % variance” hangs on.

Example 2 — wine: scaling flips a mediocre PCA into an excellent one

The lecture’s second dataset is Wine (178 samples, 13 chemical features, 3 cultivars), used to compare PCA with and without standardization through a GaussianNB classifier (notebook 10_PCA.ipynb, cell 12). Reproducing it with a fixed seed (the [NB-3] fix) (computed via the .venv, random_state=42):

X_train, X_test, y_train, y_test = train_test_split(
    features, target, test_size=0.30, random_state=42)   # NB-3 fix: add a seed

unscaled = make_pipeline(PCA(n_components=2), GaussianNB()).fit(X_train, y_train)
scaled   = make_pipeline(StandardScaler(), PCA(n_components=2), GaussianNB()).fit(X_train, y_train)
Wine, 2-component PCA → GaussianNB PC1 evr PC1+PC2 evr Test accuracy
Unscaled 0.998 0.9998 0.81
Standardized 0.362 0.550 0.98

Read the table the right way round. The unscaled PCA looks like it captures everything — 99.8 % on PC1 alone — yet classifies worst (0.81). That single component is essentially just proline, whose raw variance (≈ 98,600) dwarfs every other feature by orders of magnitude (computed), so PCA aligns PC1 with one chemical and throws away the rest. Standardize, and the variance spreads across components (36 % / 19 %), PC1+PC2 keep a more modest 55 % — and accuracy jumps to 0.98 (computed). More retained variance is not the goal; retained useful variance is, and only scaling delivers it. This is the headline limitation from Lecture 6 (slide 11/19): without standardization PCA is biased toward whichever feature happens to be measured in big numbers.

Both examples teach the same thing from opposite directions: on seeds, scaling makes the “99 %” honestly shrink to 86 %; on wine, scaling makes a useless 99.8 %-on-PC1 split spread out and the downstream accuracy soar. The explained-variance ratio is only trustworthy after standardizing.

5. Visualization

The one figure that earns its place for PCA is the cumulative explained-variance curve (a “scree”-style plot): how much of the total variance you have retained as you add components, with a horizontal line at the variance budget you are willing to keep. It turns the abstract phrase “PCA to 90 % variance” into a concrete count — read straight up from where the curve crosses the line. The data below is the standardized seeds PCA, computed in the course .venv (./.venv/Scripts/python.exe, deterministic — PCA on fixed data has no random seed to set); it is the honest, scaled version of Example 1, and it is exactly the diagnostic the exam asks for.

Static prose can say “keep components until you reach 90 %”; only the picture shows which count that is, and that the answer changes the moment you standardize — the elbow after PC3 is where the remaining components carry almost no variance (the noise tail you can safely discard for K-Means or any downstream model).

6. Diagnostics & interpretation

What to report and look at to decide whether a PCA is doing its job:

  • explained_variance_ratio_ and its cumulative sum — the headline. Report per-component and cumulative variance; choose n_components by a budget (90 %, 95 %) read off the §5 curve, or by an elbow where added components stop paying. Remember it is only meaningful after standardizing (§4).
  • Did you standardize? — the first thing to check. On raw features with mixed units the top component can be one high-variance feature in disguise (wine’s proline, §4). Lecture 6 stresses this as crucial (slide 11/19).
  • Component loadings (components_) — each component is a weighted blend of original features; inspect the weights to interpret what a component “means,” but accept that blends are inherently harder to read than single features (the interpretability limitation, slide 11/19).
  • Outlier check — because PCA is variance-driven, a few extreme points can tilt the components; scan the projection scatter (or the original features) for outliers before trusting the axes (slide 11/19).

PCA vs LDA, and choosing the number of components. Both reduce dimensions linearly, but they optimize different things: PCA is unsupervised — it keeps the directions of greatest total variance, ignoring labels — while LDA is supervised and keeps the directions of greatest class separation (Lecture 6 slide 9/19; the LDA Iris example shows LDA’s LD1 capturing ~99 % of between-class separation, which need not coincide with PCA’s top variance axis). LDA is also capped at #classes − 1 components; PCA can return up to #features. For choosing the count, PCA has no labels to validate against, so the rule is the explained-variance budget (the §5 curve), not cross-validated accuracy — that is the exam’s chosen criterion (90 %). Versus Regularization, PCA projects onto new uncorrelated axes (losing interpretability of the originals) where Ridge/Lasso shrink the original coefficients (keeping them).

7. Past-exam lens

How PCA shows up — this is core to the unsupervised assignment. In the Spring-2025 take-home (Assignment 2) the unsupervised task runs on WholesaleCustomers.csv: standardize the features, apply PCA keeping enough components for 90 % of the variance, interpret what those components represent, then feed the reduced data into K-Means (phase0/concept_inventory.md; phase0/exam_spring2025_notebook.md). Expect to (i) write the pipeline idiom from §3 — StandardScaler before PCA, the non-negotiable step (§4); (ii) use PCA(n_components=0.90) (or read the cumulative-variance curve, §5) and justify the component count; (iii) interpret the components from their loadings — “PC1 is mostly spending on X and Y” — accepting that blends are harder to read; and (iv) hand the projection to K-Means and choose k by elbow/silhouette. The grade rests on the reasoning — why standardize, why this many components, what they mean — at least as much as on the code. The classic slip to avoid: running PCA on unscaled features, which (as the wine example shows) lets one big-unit feature hijack the first component.

8. Math

Math is off. Use the Math toggle in the top bar to show the course-level derivation (and “full” for the rigorous version).

Mode A — course level. PCA stated as the course teaches it — conceptually, with no formula. Principal components are the orthogonal directions that successively maximize variance: PC1 is the direction capturing the most variance in the data, PC2 the most of the remaining variance subject to being orthogonal to PC1, and so on (Lecture 6, slide 9/19). How much you keep is summarized by the explained-variance ratio — the fraction of total variance lying along each component — which the notebook reads off as explained_variance_ratio_ and sums to decide how many components to retain (notebook 10_PCA.ipynb, cell 7: sum(pca.explained_variance_ratio_.round(2))). Lecture 6 frames the choice as an information-loss trade-off: “use explained variance to decide acceptable loss” (slide 11/19), which is exactly the §5 cumulative-variance read-off and the exam’s “90 % variance” rule. Note: Lecture 6 gives PCA only conceptually — there is no covariance-eigendecomposition, SVD, or explained-variance formula anywhere on the slides (phase0/disagreements.md [R9-5]). The formal eigen/SVD math is therefore supplemental: it lives in Mode B below, drawn from the lecture notebook’s markdown and the textbooks, not from the course deck.

Mode B — full rigor (supplemental — not on the course slides; sourced from the lecture notebook’s markdown + ESL §14.5 / ISL §12.2; phase0/disagreements.md [R9-5]). The eigen/SVD characterization the slides omit. Local notation (per phase0/notation_table.md, which records that the slides assign no symbol to PCA components — these are supplied from ESL §14.5): v_j = j-th principal-component direction (loading vector), \lambda_j = the variance along it, d_j = j-th singular value. Here \lambda is a PCA variance/eigenvalue, not a regularization strength (the Ridge/Lasso sense). Throughout, X is the n\times p data matrix with columns centered to mean zero.

Two equivalent characterizations. (i) Variance maximization (ISL §12.2.1). The first principal component is the normalized linear combination Z_1 = \phi_{11}X_1 + \dots + \phi_{p1}X_p with \sum_j \phi_{j1}^2 = 1 that has the largest sample variance (ISL 12.1); formally it solves \max_{\phi_1:\,\|\phi_1\|=1}\;\frac1n\sum_{i=1}^n\Bigl(\textstyle\sum_{j=1}^p \phi_{j1}x_{ij}\Bigr)^2 \qquad\text{(ISL 12.3),} with each later component maximizing the remaining variance subject to being orthogonal to the earlier ones. (ii) Reconstruction-error minimization (ISL §12.2.2; ESL §14.5.1). Equivalently, the first m components give the rank-m linear approximation x_{ij}\approx\sum_{k\le m} z_{ik}\phi_{jk} minimizing the squared error (ISL 12.6–12.7); ESL writes the same as fitting the affine rank-q hyperplane f(\lambda)=\mu+V_q\lambda (ESL 14.49) by least squares \min\sum_i\|x_i-\mu-V_q\lambda_i\|^2 (ESL 14.50), with solution \hat\mu=\bar x, scores \hat\lambda_i=V_q^\top(x_i-\bar x), and direction matrix V_q minimizing the projection residual (ESL 14.51–14.53). ISL 12.11 shows these two views are the same problem: total variance = variance of the kept components + reconstruction MSE, so maximizing the one minimizes the other.

Eigen/SVD solution. Form the sample covariance \Sigma=\tfrac1n X^\top X; its eigendecomposition \Sigma v_j=\lambda_j v_j gives the component directions as eigenvectors v_j ordered by eigenvalue \lambda_j (= variance along v_j), and the projection \hat X=XV keeps the leading columns of V (lecture notebook 10_PCA.ipynb, cell 1, markdown; ISL §12.2.1 footnote: “the principal component directions \phi_1,\phi_2,\dots are the ordered eigenvectors of X^\top X, and the variances of the components are the eigenvalues”). The numerically preferred route is the singular value decomposition X=UDV^\top (ESL 14.54), where the columns v_j of V are the right-singular vectors (the directions/loadings), D=\operatorname{diag}(d_1\ge\dots\ge d_p\ge0) holds the singular values, and the columns of UD are the principal components (the scores) — so \lambda_j=d_j^2/n. sklearn’s PCA uses this SVD path. The general eigen/SVD background is deferred to the linear-algebra appendix; the key result inline is that components = (right-)singular vectors/eigenvectors, variances = (squared singular values)/eigenvalues.

Explained-variance ratio. The proportion of variance explained by component j (ISL 12.10, the PVE) is \frac{\lambda_j}{\sum_k \lambda_k}=\frac{d_j^2}{\sum_k d_k^2}, which is exactly sklearn’s explained_variance_ratio_ from Mode A. “PCA to 90 % variance” is then the smallest m with \sum_{j\le m}\lambda_j\big/\sum_k\lambda_k\ge 0.90 — the §5 cumulative-variance read-off (standardized seeds: m=3, computed). ESL’s handwritten-digits example makes the same count concrete: of 256 possible components, “approximately 50 account for 90 % of the variation… 12 account for 63 %” (ESL §14.5.1). Anchored to ISL §12.2 (eqs 12.1, 12.3, 12.6–12.7, 12.10–12.11) and ESL §14.5.1 (eqs 14.49–14.54).
