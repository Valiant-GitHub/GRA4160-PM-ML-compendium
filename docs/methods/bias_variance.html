Bias–Variance Trade-off

Cross-cutting · not a model but the lens every model is read through — the single axis along which you diagnose whether a fit is too simple or too complex. The same knob recurs everywhere: polynomial degree (here), kNN neighbour count K, Decision Tree depth, and Regularization strength λ. It is also the language the Spring-2025 exam asks you to speak when comparing OLS against Ridge/Lasso.

1. Essence

Every supervised model’s expected error on new data splits into two parts you can trade against each other. Bias is error from over-simple assumptions: a model too rigid to represent the true relationship makes the same systematic mistake no matter which training sample it sees — it is consistent but wrong, and it underfits (Lecture 2, slide 5/10; Lecture 5, slide 10/11). Variance is sensitivity to the particular training set: a model flexible enough to chase the noise will fit each sample’s quirks differently, so it does well in-sample but generalizes poorly — it overfits (Lecture 5, slide 10/11). The goal is neither extreme but the sweet spot that minimizes total error — “ML is largely the art of balancing bias and variance” (Lecture 5, slide 11/11).

The trade-off is structural, not optional: making a model more complex (more polynomial terms, deeper tree, smaller K, smaller λ) lowers bias but raises variance; simplifying it does the reverse (notebook 09_Bias_variance_tradeoff.ipynb, cell 1). You cannot drive both to zero. This page is the universal frame; each method page applies it to its own complexity knob, and the cross-method showdowns line several knobs up on the same data.

What this is not: a thing you fit. There is no BiasVarianceTradeoff() estimator. It is the diagnostic vocabulary — train-vs-validation gap, learning curves, the U-shaped test-error curve — you use to decide which way to turn whatever knob your chosen model exposes (§6). The course demonstrates it concretely with polynomial regression of increasing degree on a noisy sine (§4), the cleanest possible illustration because “complexity” is just one integer.

2. When to use / when not to use

Because this is a diagnostic frame rather than a model, the usual “reach for it / reach for something else” becomes “which side are you on, and how do you tell?”

You’re under-fitting (too much bias) when…

  • Training error itself is high — the model can’t even fit the data it has seen. In §4, polynomial degree 1 on the sine leaves an obvious systematic miss (train MSE ≈ 0.21, far above the 0.04 noise floor).
  • Train and validation error are both bad and close together — a small gap but a high level. The model is consistently wrong.
  • Fix: increase complexity — add features / higher-degree terms, a deeper tree, a smaller kNN K, less regularization (smaller λ) (Lecture 5, slide 10/11: “increase complexity, add features”).

You’re over-fitting (too much variance) when…

  • Training error is low but validation/test error is much higher — a large train–test gap. This is the headline tell (§6). In §4 the degree-20 fit nails the training points yet its 10-fold cross-validated error explodes.
  • The fitted curve wiggles through individual points / noise rather than the trend (notebook 09, cell 13: “capturing the noise … as well as the underlying pattern”).
  • Predictions swing wildly when you re-draw the training sample — high sensitivity to the data you happened to get.
  • Fix: reduce complexity or variance — regularization, more training data, or a simpler model (Lecture 5, slide 10/11: “regularization, more data, simplify model”).

The whole job is to walk from one callout toward the middle. The §4 sweep makes the journey literal: degree 1 = the first callout, degree 20 = the second, degree 3–4 = the target in between.

3. Code idiom

There is no estimator to call; the idiom is the experiment that exposes the trade-off — sweep a complexity knob and read out-of-sample error with cross-validation. The course’s instrument is a polynomial-regression pipeline scored by cross_val_score (notebook 09_Bias_variance_tradeoff.ipynb, cell 5):

from sklearn.pipeline import Pipeline
from sklearn.preprocessing import PolynomialFeatures
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import cross_val_score

def polynomial_regression(degree, cv=10):
    model = Pipeline([('poly',   PolynomialFeatures(degree=degree)),
                      ('linear', LinearRegression(fit_intercept=False))])
    scores = cross_val_score(model, X, y, cv=cv)   # <-- no scoring= : returns R², not MSE
    y_pred = model.fit(X, y).predict(X)
    # ... plot data + fitted curve ...

PolynomialFeatures(degree=d) is the complexity knob: degree is to this pipeline what K is to kNN, max_depth to a tree, and alpha (=λ) to Ridge/Lasso. LinearRegression(fit_intercept=False) is deliberate — PolynomialFeatures already emits a degree-0 (constant) column, so the intercept is absorbed there (notebook 09, and notation cross-check: the bias column here is unrelated to statistical bias).

Idiom trap — this returns R², not MSE [NB-2]. In the notebook, cross_val_score(model, X, y, cv=cv) is called with no scoring= argument, so it returns the regression default — R², not MSE — even though the markdown (cell 2) says “estimate the mean squared error” and the plot label prints error={np.mean(np.abs(scores))}. The printed “error” is therefore the mean absolute R², which is not a meaningful error metric (R² can go very negative on a badly-predicted held-out fold). When you lift this idiom, do one of two things:

# Option A — keep R² but read it correctly (higher = better, ≤ 1; can be < 0):
scores = cross_val_score(model, X, y, cv=10)                          # R²

# Option B — actually measure error (what the prose intends):
scores = cross_val_score(model, X, y, cv=10,
                         scoring='neg_mean_squared_error')            # MSE = -scores

§4 reports both so the metric is never ambiguous.

4. Worked examples

Example 1 — the polynomial degree sweep (the canonical demo)

The course’s set piece (notebook 09_Bias_variance_tradeoff.ipynb, cells 3–13): 80 points of a noisy sine, fit by polynomials of growing degree.

np.random.seed(10)
X = np.sort(5 * np.random.rand(80, 1), axis=0)        # 80 points in [0, 5)
y = np.sin(X).ravel() + 0.2 * np.random.randn(80)     # sine + Gaussian noise, σ = 0.2

The noise is added with standard deviation 0.2, so the irreducible-error floor is σ² = 0.2² = 0.04 — no model, however clever, can push the expected squared error below it (this is the σ² term in §8 Mode B). Running the cell-5 pipeline for the degrees the notebook actually calls (1, 2, 3, 4, 8, 20) gives (computed with ./.venv/Scripts/python.exe, scikit-learn 1.8.0, replicating the notebook’s seed and cv=10; the notebook stores no outputs):

degree 10-fold CV MSE (lower = better) 10-fold CV R² (the notebook’s default scorer) regime
1 0.336 −7.45 underfit (high bias)
2 0.162 −5.82 improving
3 0.103 −1.36 good
4 0.073 −0.90 best of these
8 0.399 −17.0 overfitting
20 ≈ 1.14 × 10⁶ ≈ −6.3 × 10⁷ overfit (variance blow-up)

Read the MSE column: error falls from degree 1 to a minimum at degree 4, then climbs — the bias–variance U-curve. Degree 1 underfits (notebook cell 7: “too simple … high bias”); degree 20 overfits catastrophically (cell 13: “capturing the noise … high variance”), its CV MSE exploding by six orders of magnitude as the wiggly fit extrapolates wildly on held-out folds.

Why are the R² values so negative? [NB-2 in action] Two compounding reasons: (1) cross_val_score returns R² by default, and (2) the data is sorted by X with no shuffle, so each fold holds out a contiguous slice of the sine that the model — trained on the rest — predicts poorly, driving held-out R² far below 0. The notebook then takes np.mean(np.abs(scores)), turning these into large positive “errors”. They are not MSE. The MSE column is the one to trust; the R² column is shown only to reproduce, and demystify, the notebook’s printed numbers.

Example 2 — train error vs validation error: seeing the gap

Bias and variance separate cleanly when you watch in-sample (training) error and out-of-sample (CV) error together across the same sweep (computed via venv, same data/seed, scoring='neg_mean_squared_error'):

degree train MSE 10-fold CV MSE gap (CV − train)
1 0.214 0.336 0.12
3 0.050 0.103 0.05
4 0.043 0.073 0.03
8 0.043 0.399 0.36
12 0.043 ≈ 503 huge

Training MSE falls monotonically and then flattens near 0.043 ≈ the noise floor σ² = 0.04 — a model flexible enough simply memorizes the training noise, so its train error can’t beat the floor and barely tries to. The CV MSE, by contrast, bottoms out at degree 4 and then diverges. The growing gap between the two curves is variance made visible: at degree 1 the curves are close but high (bias); past degree 4 the train curve stays low while CV runs away (variance). This gap is the single most useful diagnostic in §6, and it is exactly the train-vs-test R^2 gap the OLS page flags on Hitters (0.55 vs 0.36).

6. Diagnostics & interpretation

How to tell which side you’re on, and what to do about it:

  • Train-vs-validation gap — the key tell. Low training error with much higher validation/test error ⇒ variance/overfit. Both high and close ⇒ bias/underfit. This is the train–test R^2 gap on OLS/Hitters (0.55 vs 0.36) and the train–CV gap in §4 Example 2. Always report both numbers, never just training error.
  • The validation-error U-curve (§5). Sweep the complexity knob and find the minimum of the cross-validated error; that degree/K/depth/λ is your operating point. The notebook builds intuition for this by plotting fits at degrees 1 … 20; CV & Information Criteria is the page that formalizes how to pick it (k-fold, AIC/BIC).
  • Learning curves (error vs training-set size). A high-variance model improves a lot as you add data (gap closes) — so “get more data” is a real fix for variance; a high-bias model plateaus early and adding data won’t help (Lecture 5, slide 10/11 lists “more data” as a variance remedy specifically). Why this works is visible in §8 Mode B: the linear-model variance term is \tfrac{p}{N}\sigma_\varepsilon^2 (ESL 7.12), which shrinks as the sample size N grows while the bias term does not — so adding data attacks variance, not bias. (The error-vs-N learning-curve plot itself is not in notebook 09 — which sweeps complexity, not sample size — so it is described here as the conceptual companion to the §4–§5 degree sweep rather than reproduced from a course figure.)
  • The irreducible floor. Don’t chase error below σ² (§8 Mode B). In §4, train MSE flattening at ≈ 0.043 ≈ 0.2² signals you’ve hit the noise, not a modelling failure — exactly the point the OLS synthetic example makes about a modest R^2 under large noise.

One knob, every method. The bias–variance axis is the same wherever you turn; only the dial’s name changes:

Method Complexity knob More complex (↑ variance, ↓ bias) Simpler (↑ bias, ↓ variance)
Polynomial regression (here) PolynomialFeatures(degree) higher degree lower degree
kNN neighbours K small K (e.g. 1) large K
Decision Trees tree depth / leaf size deep tree shallow / pruned
Ridge / Lasso penalty λ (sklearn alpha) small λ (→ OLS) large λ

Note the inversions: for kNN and regularization the small setting is the high-variance one. This table is the spine of the cross-method showdowns.

7. Past-exam lens

How the trade-off shows up. In the Spring-2025 take-home (Assignment 1, on Hitters.csv), the bias–variance trade-off is the interpretation the grader wants: fit OLS as the baseline, then Ridge/Lasso with cross-validated alpha, and explain the trade-off — why shrinkage (more λ ⇒ more bias, less variance) closes the train–test gap and can improve out-of-sample error, even though it makes the in-sample fit worse (phase0/exam_spring2025_notebook.md; concept-inventory entry 7). Expect to (i) name the train–test performance gap as the variance symptom (§6), (ii) frame regularization’s effect in bias–variance terms, and (iii) argue why trading a little bias for a lot less variance is worth it on a dataset with many correlated predictors. The vocabulary of this page — bias, variance, overfit/underfit, irreducible error — is what earns the interpretation marks; the bias–variance trade-off is also a recurring framing concept across Lectures 1, 2, 3, and 5.

8. Math

Math is off. Use the Math toggle in the top bar to show the course-level decomposition (and “full” for the rigorous version with the irreducible-error term).

Mode A — course level. The course states the trade-off as a two-term decomposition of a model’s total error (Lecture 5, slide 10/11): \text{Total Error} = \text{Bias}^2 + \text{Variance}. Reading it. Bias is the systematic part: error “from erroneous assumptions (e.g. assuming linear when quadratic),” a model that “misses relevant relations” and underfits — its fix is to increase complexity, add features (Lecture 5, slide 10/11; Lecture 2, slide 5/10). Variance is the unstable part: error “from sensitivity to small fluctuations in the training set,” a model that “models random noise” and overfits — its fix is regularization, more data, simplify the model (Lecture 5, slide 10/11). Squaring the bias puts both terms in the same (squared-error) units so they add. Turning up complexity (higher polynomial degree, smaller kNN K, deeper tree, smaller Ridge/Lasso λ) shrinks the first term but inflates the second; the goal is the sweet spot where their sum is smallest — “ML is largely the art of balancing bias and variance” (Lecture 5, slide 11/11). The §4 sweep is this equation made numerical: the U-shaped CV-error curve is Bias² falling and Variance rising, traced out as degree grows. The course form deliberately stops here; the irreducible noise floor \sigma^2 that the full version adds is omitted on the slide [R9-2] — see Mode B. Same decomposition stub in the math appendix.

Mode B — full rigor. (Anchored to ESL §7.3 “The Bias–Variance Decomposition”, eqs 7.9–7.12.) Assume the data are generated as Y = f(X) + \varepsilon with \operatorname{E}[\varepsilon]=0 and \operatorname{Var}(\varepsilon)=\sigma_\varepsilon^2. Fit \hat f on a random training set and evaluate the expected prediction error at a fixed input point x_0 under squared-error loss. ESL derives (eq 7.9): \begin{aligned} \operatorname{Err}(x_0) &= \operatorname{E}\!\left[(Y - \hat f(x_0))^2 \mid X = x_0\right]\\ &= \sigma_\varepsilon^2 + \bigl[\operatorname{E}\hat f(x_0) - f(x_0)\bigr]^2 + \operatorname{E}\bigl[\hat f(x_0) - \operatorname{E}\hat f(x_0)\bigr]^2\\ &= \underbrace{\sigma_\varepsilon^2}_{\text{Irreducible Error}} + \underbrace{\operatorname{Bias}^2(\hat f(x_0))}_{} + \underbrace{\operatorname{Var}(\hat f(x_0))}_{}. \end{aligned} Where the three terms come from. The expectation is over both the noise \varepsilon and the random training set. The trick is to add and subtract the mean prediction \operatorname{E}\hat f(x_0) inside the squared error and expand. Writing y = f(x_0)+\varepsilon and splitting y - \hat f(x_0) = \underbrace{\varepsilon}_{} + \underbrace{(f(x_0) - \operatorname{E}\hat f(x_0))}_{} + \underbrace{(\operatorname{E}\hat f(x_0) - \hat f(x_0))}_{}, the square produces three diagonal terms — \operatorname{E}[\varepsilon^2]=\sigma_\varepsilon^2, the constant squared bias, and the variance \operatorname{E}[(\hat f(x_0)-\operatorname{E}\hat f(x_0))^2] — plus three cross-terms that all vanish: \varepsilon is independent of \hat f with mean zero, and \operatorname{E}[\hat f(x_0)-\operatorname{E}\hat f(x_0)]=0 kills the bias×variance cross-term. This is exactly ESL’s middle line of (7.9). The first term \sigma_\varepsilon^2 “cannot be avoided no matter how well we estimate f(x_0), unless \sigma_\varepsilon^2 = 0” (ESL §7.3) — it is the floor the course slide drops [R9-2]; in §4’s noisy sine the noise has SD 0.2, so \sigma_\varepsilon^2 = 0.2^2 = 0.04, precisely where the train-MSE curve flattens. “Typically the more complex we make the model \hat f, the lower the (squared) bias but the higher the variance” (ESL §7.3) — the formal statement of the trade-off.

Special cases ESL gives. For k-nearest-neighbour regression with the training inputs held fixed, the decomposition takes the explicit form (ESL 7.10) \operatorname{Err}(x_0) = \sigma_\varepsilon^2 + \Bigl[f(x_0) - \tfrac{1}{k}\textstyle\sum_{\ell=1}^{k} f(x_{(\ell)})\Bigr]^2 + \frac{\sigma_\varepsilon^2}{k}, making the knob explicit: averaging over more neighbours shrinks the variance \sigma_\varepsilon^2/k but the bias term (the gap between f(x_0) and the average of f over the k neighbours) typically grows — small k = high variance, large k = high bias, the inversion flagged for kNN in §6. For a linear model \hat f_p(x_0)=x_0^\top\hat\beta fit by least squares on p predictors, the variance term becomes \lVert \mathbf h(x_0)\rVert^2 \sigma_\varepsilon^2 where \mathbf h(x_0)=\mathbf X(\mathbf X^\top\mathbf X)^{-1}x_0 (ESL 7.11); averaging over the sample, the in-sample error is (ESL 7.12) \frac{1}{N}\sum_{i=1}^{N}\operatorname{Err}(x_i) = \sigma_\varepsilon^2 + \frac{1}{N}\sum_{i=1}^{N}\bigl[f(x_i)-\operatorname{E}\hat f(x_i)\bigr]^2 + \frac{p}{N}\sigma_\varepsilon^2, so here model complexity is literally p: adding predictors lowers bias but inflates the variance term \tfrac{p}{N}\sigma_\varepsilon^2 linearly — the algebraic root of the train–test R^2 gap on OLS/Hitters and the reason Ridge trades a little bias for a smaller variance term (ESL §7.3 develops this into its model-bias/estimation-bias split, eqs 7.13–7.14). The course’s \text{Bias}^2 + \text{Variance} (Mode A) is this decomposition with \sigma_\varepsilon^2 set aside. Same stub in the math appendix.
