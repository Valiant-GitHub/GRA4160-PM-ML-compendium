Logistic Regression

Linear family · the default first classifier for a binary target, and the linear-boundary baseline every other classifier is judged against. It is the classification analogue of OLS — same linear machinery, aimed at a probability instead of a continuous number. Siblings: LDA (also a linear boundary, but assumes Gaussian classes with shared covariance), Adaline (the same gradient-descent update, with MSE + linear activation instead of cross-entropy + sigmoid), kNN and Decision Trees (non-parametric, non-linear alternatives).

1. Essence

Logistic regression predicts the probability that an observation belongs to the positive class. It does so with the same linear core as OLS — one coefficient per predictor plus an intercept, combined into a single number z = \beta_0 + \beta_1 x_1 + \dots + \beta_p x_p (the net input) — but then passes that number through the sigmoid function \sigma(z) = 1/(1+e^{-z}), which squashes any real value into [0,1] so it can be read as a probability (Lecture 4, slide 7/11). To turn a probability into a class label you apply a threshold, by default 0.5: predict class 1 when \sigma(z) \ge 0.5, else class 0 (Lecture 8, slide 24/29). Despite the name, it is a classification technique, not a regression one (notebook 06_Logistic_regression.ipynb, cell 1).

The reason the linear-plus-sigmoid form is natural, not arbitrary, is that it makes the log-odds linear in the predictors: \log\!\big(\pi/(1-\pi)\big) = \beta_0 + \beta_1 x_1 + \dots + \beta_p x_p, where \pi is the probability of the positive class (Lecture 4, slide 6/11; the course slides and notebooks write this probability as p — here we use \pi to avoid colliding with p = number of predictors, see the notation table). This gives each coefficient a clean reading: a one-unit increase in z multiplies the odds \pi/(1-\pi) by e \approx 2.718 (Lecture 4, slide 8/11). That interpretability — coefficients as effects on the log-odds — is the whole appeal, the same way it is for OLS.

It is a parametric model fit by maximum likelihood (equivalently, by minimizing the negative log-likelihood, i.e. the cross-entropy loss). Compared with its nearest neighbors: LDA draws a linear boundary too but gets there by modelling each class as Gaussian with a shared covariance — logistic regression makes no distributional assumption about the predictors and estimates the boundary directly; Adaline is the identical gradient-descent learner with the sigmoid swapped for a linear activation and cross-entropy swapped for MSE (Lecture 8, slides 27–28/29); and kNN and trees drop the linear-boundary assumption entirely.

2. When to use / when not to use

Reach for logistic regression when…

  • The target is a class (binary first; multi-class via One-vs-All or softmax) and you want calibrated probabilities, not just a hard label — e.g. “chance of survival”, “chance of disease” (Lecture 8, slide 24/29).
  • You want interpretable coefficients: each \beta_j is the change in log-odds per unit of x_j, and e^{\beta_j} is the odds multiplier — the classification counterpart of reading OLS slopes.
  • You expect a roughly linear decision boundary in the feature space (or one you can linearize with transforms/interactions).
  • You need a fast, transparent baseline before reaching for trees or neural nets. It is a natural candidate classifier for the Spring-2025 exam’s classification task (see §7).

Reach for something else when…

  • The classes are well-separated Gaussians with similar covariance → LDA uses that structure and can be more stable, especially with little data or perfectly separable classes (where plain logistic regression’s coefficients can diverge). Lecture 4 (slide 4/11) lists LDA’s assumptions explicitly.
  • The boundary is clearly non-linear and you don’t want to hand-engineer the form → Decision Trees / Random Forests (axis-aligned splits) or kNN capture curvature automatically.
  • You want raw flexibility / a stepping stone to neural nets → a single sigmoid unit is logistic regression; stacking them gives an MLP. Adaline is the same learner with a linear output.
  • Predictors heavily outnumber observations or are strongly correlated → coefficients become unstable; use the built-in L2/L1 penalty (the C/penalty arguments, §3) — the classification echo of Ridge/Lasso.

3. Code idiom

The canonical course idiom is scikit-learn’s LogisticRegression (notebook 06, on Titanic); the course also builds the model from scratch by gradient descent (notebook 15, on Iris) to show the sigmoid + cross-entropy mechanics — and to make the Adaline → logistic link concrete.

Canonical (sklearn) — (notebook 06_Logistic_regression.ipynb, cell 7)

from sklearn.linear_model import LogisticRegression

log_reg = LogisticRegression(solver='lbfgs', max_iter=500)  # lbfgs = quasi-Newton optimizer
log_reg.fit(X_train, y_train)                                # X: (n_samples, n_features), y in {0,1}
log_reg.predict(X_test)                                      # hard labels at the 0.5 threshold
log_reg.predict_proba(X_test)                                # [P(class 0), P(class 1)] per row
log_reg.coef_        # the log-odds slopes β₁…β_p
log_reg.intercept_   # the intercept β₀

solver='lbfgs' is the optimizer (a quasi-Newton method); max_iter=500 raises the iteration cap from the default 100 so the optimizer converges on this data. Everything else is default: penalty='l2', C=1.0 (inverse regularization strength — smaller C means stronger shrinkage, the classification analogue of a larger Ridge alpha), class_weight=None. For imbalanced classes, class_weight='balanced' and tuning C/penalty are the standard knobs (real sklearn parameters; values left default as they are not changed in the notebook).

From scratch — gradient descent (notebook 15_LogisticRegression.ipynb, cell id a342d4e2). This is Adaline with two changes: a sigmoid activation and a cross-entropy loss. Per Lecture 8 (slides 27–28/29) the gradient-descent update is unchanged — both reduce to -\tfrac1n\sum(y-\text{activation})\,x_j — only the activation inside differs ([disagreements R9-11]):

class LogisticRegressionGD:
    def __init__(self, eta=0.01, n_iter=50, random_state=1):   # course uses eta=0.3, n_iter=1000
        self.eta = eta; self.n_iter = n_iter; self.random_state = random_state

    def fit(self, X, y):
        rgen = np.random.RandomState(self.random_state)
        self.w_ = rgen.normal(loc=0.0, scale=0.01, size=X.shape[1])  # small random init
        self.b_ = 0.0
        self.losses_ = []
        for i in range(self.n_iter):
            output = self.activation(self.net_input(X))      # σ(z), the predicted probability
            errors = (y - output)                            # y − σ(z)
            self.w_ += self.eta * X.T.dot(errors) / X.shape[0]   # vectorized GD step (÷ n)
            self.b_ += self.eta * errors.mean()
            output_clipped = np.clip(output, 1e-10, 1.0 - 1e-10)         # avoid log(0)
            loss = -y.dot(np.log(output_clipped)) - (1 - y).dot(np.log(1 - output_clipped))
            self.losses_.append(loss / X.shape[0])           # binary cross-entropy per sample

    def net_input(self, X):   return np.dot(X, self.w_) + self.b_       # z = w·x + b
    def activation(self, z):  return 1. / (1. + np.exp(-np.clip(z, -250, 250)))  # sigmoid (clipped)
    def predict(self, X):     return np.where(self.activation(self.net_input(X)) >= 0.5, 1, 0)

The course instantiates this with LogisticRegressionGD(eta=0.3, n_iter=1000, random_state=1) (cell id 50ee34c8) — a learning rate eta (\eta) of 0.3 and n_iter 1000 epochs, well above the class defaults eta=0.01, n_iter=50.

Idiom variation worth knowing — multi-class via One-vs-All. For 3 classes the from-scratch notebook trains one binary detector per class and stacks their sigmoid outputs, then takes the argmax (notebook 15_LogisticRegression.ipynb, cell id f4432549):

probabilities = np.zeros((X.shape[0], 3))
for k in range(3):
    y_k = np.where(y_all == k, 1, 0)                 # class k vs the rest
    lrgd_k = LogisticRegressionGD(eta=0.3, n_iter=1000, random_state=1).fit(X, y_k)
    probabilities[:, k] = lrgd_k.activation(lrgd_k.net_input(X))
predicted = np.argmax(probabilities, axis=1)         # pick the most confident detector

The notebook explicitly warns these three sigmoid outputs do not sum to 1 — each is an independent binary detector; for true probabilities that sum to 1 you would use softmax (multinomial) regression instead (cell id 6b3b3496). sklearn’s LogisticRegression does softmax/OvA automatically when y has more than two classes.

4. Worked examples

Example 1 — Titanic survival with sklearn

The course’s canonical example predicts survival on the Titanic training set (notebook 06_Logistic_regression.ipynb, cells 3–11). After dropna() the 891-row frame collapses to 183 rows (the sparse Cabin column drives most of the loss, biasing the sample toward 1st-class passengers — a real data quirk the notebook does not flag), Sex is encoded male=1/female=0, and six features are used with an 80/20 split (random_state=15):

df = pd.read_csv('../data/titanic/train.csv').dropna()        # 891 → 183 rows
df['Sex'] = df['Sex'].apply(lambda x: 1 if x == 'male' else 0)
X = df[['Pclass', 'Sex', 'Age', 'SibSp', 'Parch', 'Fare']]
y = df['Survived']
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=15)
log_reg = LogisticRegression(solver='lbfgs', max_iter=500).fit(X_train, y_train)

This yields test accuracy ≈ 0.892 (33/37 correct), well above either trivial baseline (the 37-row test set is 20 survived / 17 died, so always-guessing the majority class “survived” scores 0.541 and always-guessing “died” scores 0.459) — (computed via the course venv, random_state=15; the notebook stores no outputs). The confusion matrix is [[13, 4], [0, 20]]: every actual survivor is caught (recall 1.00 for class 1) at the cost of 4 false alarms (class-0 recall 0.76). The fitted coefficients read directly as log-odds effects:

Feature Pclass Sex (male=1) Age SibSp Parch Fare Intercept
\beta −0.33 −2.14 −0.02 +0.14 −0.24 +0.002 +3.25

(computed, same run.) The dominant effect is Sex: being male carries \beta \approx -2.14, so it multiplies the odds of survival by e^{-2.14} \approx 0.12 versus female — the “women first” pattern, read straight off the coefficient via the odds interpretation of Lecture 4 (slide 8/11). Pclass is negative (higher class number = lower class = lower survival odds), as expected.

Example 2 — predicting a probability (synthetic)

A minimal demo shows that the model’s output really is the sigmoid’s probability (notebook 06_Logistic_regression.ipynb, cell 14). Four points lie on a perfectly separable line (y=0 for the first two, y=1 for the last two); a new point [5, 10] extends the y=1 side:

X_synth = np.array([[1, 2], [2, 4], [3, 6], [4, 8]]); y_synth = np.array([0, 0, 1, 1])
clf = LogisticRegression(solver='lbfgs').fit(X_synth, y_synth)
clf.predict_proba([[5, 10]])    # → [[0.0063, 0.9937]]
clf.predict([[5, 10]])          # → [1]

The model returns P(class 1) ≈ 0.994 (computed via venv; the notebook stores no output) — high confidence, because the point sits firmly on the positive side of the boundary. This is predict_proba exposing \sigma(z) directly; predict is just that value thresholded at 0.5.

Example 3 — from-scratch GD and One-vs-All on Iris

The from-scratch LogisticRegressionGD is fit on Iris (notebook 15_LogisticRegression.ipynb). On the binary problem (first 100 rows, Setosa vs Versicolor, sepal+petal length), with eta=0.3, n_iter=1000, the cross-entropy loss falls from ≈ 0.69 (the -\ln 0.5 of a random start) to ≈ 0.006, reaching 100% training accuracy — these two classes are linearly separable, so the GD learner drives the loss almost to zero (computed via venv, random_state=1; the notebook stores no outputs). Extending to all four features (Example 2 in the notebook) also gives 100% training accuracy.

The 3-class One-vs-All extension (cell id f4432549) trains three detectors on all 150 rows and takes the argmax, giving overall training accuracy ≈ 0.91 (computed, same run). The errors concentrate where Versicolor and Virginica overlap: per-class recall is 1.00 (Setosa), 0.98 (Versicolor), but only 0.74 (Virginica) — the limit of a linear boundary on classes that are not linearly separable, exactly the case where you would reach for kNN or a tree.

The Titanic example uses dropna() on the full frame, which silently discards 79% of rows — a reminder that preprocessing choices can matter more than the model. See the classification showdown for logistic vs LDA vs kNN vs tree on a shared 2-feature boundary.

6. Diagnostics & interpretation

What to report and look at to decide whether a logistic model is working:

  • Accuracy vs a baseline — compare against the majority-class rate (Titanic test: 0.892 vs the 0.541 majority-class baseline; 0.459 is the minority “always-died” rate). Accuracy alone is misleading on imbalanced data, so also report the confusion matrix.
  • Confusion matrix + classification report — precision, recall, F1 per class (notebook 06, cell 11). These expose where errors fall (the Titanic model trades false positives for perfect survivor recall). On imbalanced problems these matter more than accuracy.
  • Coefficients as log-odds / odds ratios — read the sign and magnitude of each \beta_j; e^{\beta_j} is the odds multiplier per unit. As with OLS, only compare magnitudes after checking feature scale, and watch for sign flips from correlated predictors.
  • Threshold tuning — the 0.5 cut is a default, not a law. Lower it (e.g. 0.3) to catch more positives at the cost of more false alarms; raise it (0.7) for the reverse. The notebook leaves this as an exercise (cell 12).
  • Probability calibration — predict_proba gives probabilities; check they are sensible (well-separated data pushes them toward 0/1, as in the synthetic example’s 0.994).

Comparative diagnostic vs siblings: logistic regression gives you coefficients as odds ratios (interpretable effect sizes) where LDA gives you class means and a shared covariance (a generative story), and a Random Forest gives feature importances (rankings, not “+1 unit ⇒ ×e odds”). All three can draw similar boundaries on separable data; choose the one whose output answers your question. Logistic and LDA are both linear — they differ in assumptions, not in boundary shape.

7. Past-exam lens

How logistic regression shows up. It is a candidate classifier for the Spring-2025 take-home’s classification task (Assignment 4), alongside kNN, trees, and others (phase0/concept_inventory.md). Expect to (i) write the LogisticRegression(solver='lbfgs', max_iter=500) idiom from §3, (ii) report accuracy plus the confusion matrix / classification report against a sensible baseline, and (iii) interpret the coefficients as log-odds / odds ratios — the grade rests on the justification, e.g. explaining the dominant Sex effect via the odds interpretation, at least as much as on the code. The from-scratch GD version (notebook 15) and the Adaline link (Lecture 8) are theory the exam can probe conceptually (“how is logistic regression obtained from Adaline?” → swap MSE→cross-entropy, linear→sigmoid; the GD step is unchanged). Logistic regression has not appeared as a stand-alone derivation question; it appears as a classification baseline.

8. Math

Math is off. Use the Math toggle in the top bar to show the course-level derivation (and “full” for the rigorous version).

Mode A — course level. The course builds logistic regression in three steps (Lecture 4, slides 6–8/11; Lecture 8, slides 23–28/29; notebooks 06 cell 1 and 15 cell id a342d4e2).

1. From log-odds to the sigmoid. The model assumes the log-odds (logit) of the positive class are linear in the predictors (Lecture 4, slide 6/11): \log\!\frac{\pi}{1-\pi} = z = \beta_0 + \beta_1 x_1 + \dots + \beta_p x_p , where \pi is the probability of the positive class and z the net input (the slides write \pi as p and use x_1\dots x_k; here \pi avoids colliding with p = #predictors — see the notation table). Solving for \pi exponentiates the odds, \pi/(1-\pi)=e^{z}, and rearranges to the logistic sigmoid (Lecture 4, slides 7–8/11; Lecture 8, slide 23/29): \pi = \sigma(z) = \frac{e^{z}}{1+e^{z}} = \frac{1}{1+e^{-z}} , which squashes any real z into (0,1) — flat in the tails, with \sigma(0)=0.5. Reading it: because the logit is linear, a one-unit rise in z adds 1 to the log-odds and so multiplies the odds \pi/(1-\pi) by e\approx 2.718 (Lecture 4, slide 8/11); each e^{\beta_j} is the odds multiplier per unit of x_j.

2. The loss — binary cross-entropy. Fitting maximizes likelihood, equivalently minimizes the negative log-likelihood, the cross-entropy loss (Lecture 8, slide 25/29): L = \sum_{i=1}^{n}\Bigl[-y_i\log\sigma(z_i) - (1-y_i)\log\bigl(1-\sigma(z_i)\bigr)\Bigr], reported per-sample as L/n in the notebook. For a single point this is -\log\sigma(z_i) when y_i=1 and -\log(1-\sigma(z_i)) when y_i=0 — zero for a confident correct call, growing without bound as the prediction goes confidently wrong (Lecture 8, slide 26/29).

3. The gradient-descent update. There is no closed form (unlike OLS), so the course fits by gradient descent. Differentiating the cross-entropy through the sigmoid collapses to the same clean form as least squares (Lecture 8, slide 28/29; notebook 15, cell id a342d4e2): \frac{\partial L}{\partial w_j} = -\frac1n\sum_{i=1}^{n}\bigl(y_i - \sigma(z_i)\bigr)\,x_{ij}, \qquad w_j \leftarrow w_j + \eta\cdot\frac1n\sum_{i=1}^{n}\bigl(y_i - \sigma(z_i)\bigr)\,x_{ij}, with learning rate \eta (the course uses \eta=0.3). The bias updates the same way with x_{ij}\equiv 1. The key course point: this is structurally identical to Adaline’s update — Adaline uses MSE with a linear activation z, logistic uses cross-entropy with the sigmoid \sigma(z), but both reduce to -\tfrac1n\sum_i(y_i-\text{activation}_i)\,x_{ij}; only the activation inside differs (Lecture 8, slides 27–28/29; [disagreements R9-11]). See the gradient-descent appendix.

Mode B — full rigor. (Anchored to ESL §4.4 “Logistic Regression”, eqs 4.17–4.26, with ISL §4.3, eqs 4.4–4.5.) ESL derives the model from the desire to make the posterior class probabilities linear in x on the logit scale while keeping them in [0,1]. For two classes the model is the single logit \log\frac{\Pr(G=1\mid X=x)}{\Pr(G=2\mid X=x)} = \beta_0 + \beta^\top x \qquad \text{(ESL 4.17, two-class case)}, which inverts to \Pr(G=1\mid X=x) = e^{\beta_0+\beta^\top x}/\bigl(1+e^{\beta_0+\beta^\top x}\bigr) (ESL 4.18; ISL 4.2) — the sigmoid. ISL gives the same logit and odds relations directly: p(X)/(1-p(X)) = e^{\beta_0+\beta^\top x} (ISL 4.3) and \log\bigl(p(X)/(1-p(X))\bigr)=\beta_0+\beta^\top x (ISL 4.4).

Maximum likelihood (Bernoulli). Code the two-class response as y_i\in\{0,1\} and write p(x_i;\beta)=\Pr(G=1\mid x_i). Each observation is Bernoulli, so the conditional log-likelihood for N points is \ell(\beta) = \sum_{i=1}^{N}\Bigl\{ y_i\log p(x_i;\beta) + (1-y_i)\log\bigl(1-p(x_i;\beta)\bigr)\Bigr\} = \sum_{i=1}^{N}\Bigl\{ y_i\,\beta^\top x_i - \log\bigl(1+e^{\beta^\top x_i}\bigr)\Bigr\} \qquad \text{(ESL 4.20)}, where x_i absorbs a leading 1 for the intercept. This is exactly the negative cross-entropy of Mode A — maximizing \ell minimizes the course’s loss — and ISL writes the same object as the likelihood \ell(\beta_0,\beta_1)=\prod_{i:y_i=1}p(x_i)\prod_{i':y_{i'}=0}(1-p(x_{i'})) (ISL 4.5).

Score equations and no closed form. Setting \partial\ell/\partial\beta=0 gives the p+1 score equations \frac{\partial\ell(\beta)}{\partial\beta} = \sum_{i=1}^{N} x_i\bigl(y_i - p(x_i;\beta)\bigr) = 0 \qquad \text{(ESL 4.21)}, which are nonlinear in \beta (since p depends on \beta through the sigmoid) — hence, unlike OLS’s normal equations, there is no closed form. The first component (the intercept’s) forces \sum_i p(x_i;\beta)=\sum_i y_i: the mean fitted probability matches the observed positive rate.

Newton–Raphson / IRLS. ESL solves the score equations with Newton–Raphson, using the Hessian \frac{\partial^2\ell(\beta)}{\partial\beta\,\partial\beta^\top} = -\sum_{i=1}^{N} x_i x_i^\top\,p(x_i;\beta)\bigl(1-p(x_i;\beta)\bigr) \qquad \text{(ESL 4.22)}, which is negative definite, so \ell is concave and the maximizer is unique (when it exists). In matrix form, with \mathbf{p} the fitted-probability vector and \mathbf{W}=\mathrm{diag}\bigl(p_i(1-p_i)\bigr), the gradient is \mathbf{X}^\top(\mathbf{y}-\mathbf{p}) (ESL 4.24) and the Newton step rearranges into a weighted least squares solve \beta^{\text{new}} = (\mathbf{X}^\top\mathbf{W}\mathbf{X})^{-1}\mathbf{X}^\top\mathbf{W}\mathbf{z}, \qquad \mathbf{z} = \mathbf{X}\beta^{\text{old}} + \mathbf{W}^{-1}(\mathbf{y}-\mathbf{p}) \qquad \text{(ESL 4.26–4.27)}, on the adjusted response \mathbf{z}. Because \mathbf{W} and \mathbf{z} change each iteration, this is iteratively reweighted least squares (IRLS) (ESL 4.28). (sklearn’s default lbfgs solver from §3 is a quasi-Newton method targeting this same concave objective.) Convergence is typical but not guaranteed; \beta=0 is a good start. On perfectly separable data the MLE diverges to \pm\infty — the motivation for the L2/L1 penalties of §2–3 (ESL §4.4.4).

The Adaline→logistic equivalence, proved. The course claims the gradient step is identical to Adaline’s [R9-11]. The score (ESL 4.24) is \mathbf{X}^\top(\mathbf{y}-\mathbf{p}), i.e. \partial L/\partial w_j = -\sum_i(y_i-\sigma(z_i))x_{ij} for the negative log-likelihood. Adaline minimizes L=\tfrac{1}{2n}\sum_i(y_i-z_i)^2 with linear activation a_i=z_i, whose gradient is \partial L/\partial w_j = -\tfrac1n\sum_i(y_i-z_i)x_{ij} (Lecture 8, slide 20/29). Both have the form -\tfrac1n\sum_i(y_i-a_i)x_{ij}; the only difference is a_i=z_i (Adaline) versus a_i=\sigma(z_i) (logistic) — so swapping MSE→cross-entropy and linear→sigmoid leaves the update template unchanged, which is why the slide labels the derivation an “optional home exercise” (Lecture 8, slides 27–28/29). The non-trivial step is that the sigmoid’s derivative \sigma'(z)=\sigma(z)(1-\sigma(z)) cancels exactly against the cross-entropy denominators, leaving the bare residual y_i-\sigma(z_i). See the maximum-likelihood appendix.
