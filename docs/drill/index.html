Drill — Index

Drill section · This is the practice hub: one page per drillable artefact — the Spring-2025 take-home exam (catalogued as a lens, never solved) and the six course exercises. Each page works the method idioms in context. Use the filters below to find a drill by method family (linear / tree / unsupervised / neural / cross-cutting), by type (exam vs exercise), or by dataset. Every tag here is taken straight from that drill’s extract — the exam’s structure from phase0/exam_spring2025_notebook.md, each exercise’s methods and dataset from its phase0/exercise_0N_*.md — so a tag means the drill actually uses that method on that data; nothing is invented. For the order in which to work them and which method pages to read first, see the exercise dependency map.

New here? Don’t pick at random — follow the path. The exercise dependency map lays out the suggested study order (1 → 6): preprocessing first (Titanic), then a from-scratch classifier (spam / naive Bayes), regression with shrinkage (house prices), a multiclass bake-off (MNIST digits), the evaluation toolkit (model selection), and finally unsupervised segmentation (customer segmentation). The filter on this page is for finding a drill; that map is for sequencing them.

The one drill that mirrors the real thing. The Spring-2025 exam drill walks the representative 30-hour take-home format — four assignments (regularized regression on Hitters, clustering on WholesaleCustomers, ensembles on WDBC, a classification challenge on SimulatedData) — as a lens on how the methods are examined, never as solved answers. Read it to see which method pages each assignment leans on and how the pipeline-style workflow (load → EDA → encode/scale → split → tune via CV → evaluate → compare → interpret) recurs across all four (phase0/exam_spring2025_notebook.md).

Pick a type, family, and dataset to narrow the list. “Any” leaves that filter open. The family colors match the rest of the site (linear · tree · unsupervised · neural · cross-cutting). A drill can belong to more than one family; it matches a family filter if any of its families fits. viewof familySel = Inputs.select(
  new Map([["Any family", "any"], ...allFamilies.map(f => [famLabel[f], f])]),
  {label: "Method family", value: "any"}
)
viewof datasetSel = Inputs.select(
  ["any", ...allDatasets],

)

Note

Two drills depend on datasets not present in the repo. Exercise 02 (spam) needs the SMS Spam Collection ([DATA-1] — the solution loads data/smsspamcollection/SMSSpamCollection.csv, absent locally) and exercise 06 (segmentation) needs the UCI Bank Marketing file ([DATA-2] — data/bank_marketing_data_set/.../bank-additional-full.csv, also absent). Both drill pages are written from the VHL solution extracts, but the code blocks won’t run until those files are supplied. Everything else (Titanic, house-prices, and the sklearn built-ins digits/iris) is available or self-contained.
